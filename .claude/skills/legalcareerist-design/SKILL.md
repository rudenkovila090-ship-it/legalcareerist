# Дизайн-система legalcareerist.ru

Сайт — Vite + React 19 + TypeScript + Tailwind CSS v4, RU-only контент. Ниже — то, что уже
установлено в кодовой базе. Задача этого скилла не «придумать красиво», а **не изобретать
заново** то, что уже есть, и добавлять новое так, чтобы оно выглядело частью той же системы.

## 0. Логотип — точная спецификация, не перерисовывать на глаз

Метка «4 полоски» — 4 линии ОДИНАКОВОЙ длины, каждая следующая (слева направо)
сдвинута выше предыдущей лесенкой (не разной высоты, как могло показаться на
ранних версиях — это была ошибка, дважды исправленная по референсу заказчика).
Используется и в шапке (`src/components/Header.tsx`), и в фавиконе
(`public/favicon.svg`) — координаты и толщина линии (strokeWidth) должны
совпадать 1:1 в обоих местах. Цвет — жестко `#283953` (не `currentColor`/
`text-ink`), заказчик явно просил вернуть именно этот hex, а не полагаться
на наследование, которое может визуально "тускнеть".

```tsx
{/* viewBox обрезан по содержимому (не 0 0 100 100 — там оставался пустой
    хвост справа от x=65 до 100, из-за которого flex-gap не мог реально
    подвинуть текст ближе, упираясь в пустой бокс SVG). width класс (w-7)
    подобран под новое соотношение сторон viewBox (50:100 = 1:2, при h-14). */}
<svg viewBox="20 0 50 100" className="h-14 w-7" stroke="#283953" strokeWidth="5" strokeLinecap="round" fill="none">
  <line x1="26" y1="88" x2="26" y2="48" />
  <line x1="39" y1="74" x2="39" y2="34" />
  <line x1="52" y1="60" x2="52" y2="20" />
  <line x1="65" y1="46" x2="65" y2="6" />
</svg>
```

Если когда-нибудь понадобится подогнать логотип под новый референс — меняй все
4 линии сохраняя эту закономерность (одинаковая длина 40, шаг по Y 14), и
обязательно обнови оба файла разом, не только один (у favicon.svg свой полный
viewBox `0 0 100 100` с фоном-плашкой — там обрезка viewBox не нужна, это
самостоятельная иконка, а не пара с текстом). strokeWidth менялся уже 5 раз по
правкам заказчика (11 → 9 → 6 → 4 → 3 → 5, в обратную сторону — толще, но
тоньше исходного) — не считай, что тренд всегда "тоньше", ориентируйся на
последний запрос. Шаг по X дважды сокращали (23 → 16 → 13). Когда просят "линии
уже/жирнее" — трогай ТОЛЬКО strokeWidth, не размер иконки (`h-14`/`w-7`) — это
разные ручки, заказчик отдельно уточнял "линии меньше не делай", имея в виду
именно габарит иконки. Цвет ВСЕГДА остаётся `stroke="#283953"` буквально (не
через opacity/currentColor) — заказчик отдельно предупредил не делать линии
тусклее ни при утоньшении, ни при утолщении.

**Текст лого в шапке** — не «Карьерный Юрист» в одну строку, а две строки
(«Карьерный» / «юрист», второе слово со строчной буквы, как на фирменном лого),
крупным кеглем (`text-lg`, не `text-sm` — заказчик отдельно просил увеличить),
шрифтом `.font-logo` (PT Sans 700 — цифровой аналог Helios для кириллицы, весь
остальной сайт на Inter), вплотную к иконке (`gap-0.5` — заказчик несколько раз
подряд просил подвинуть название левее; если попросят ещё ближе, следующий шаг —
`gap-0`, а не уменьшение самого текста). Иконка (`h-14`) на референсе заметно
ВЫШЕ двухстрочного текстового блока — выступает за его пределы и сверху, и снизу
(это не равные по высоте элементы, ошибка была именно в этом на промежуточной
версии) — если поменяешь размер текста лого, высота иконки должна остаться
заметно больше, не подгоняться вровень.

## 1. Токены (`src/index.css`)

```css
@theme {
  --font-sans: "Inter", ui-sans-serif, system-ui, sans-serif;
  --color-ink: #283953;        /* основной текст/фон тёмных блоков */
  --color-gold: #45608a;       /* акцент на светлом фоне (eyebrow-подписи) */
  --color-gold-light: #6f93c4; /* акцент на тёмном фоне (bg-ink) */
  --color-paper: #ffffff;      /* фон страницы */
}
```

Имена `gold`/`gold-light`/`paper` исторические (более ранняя версия была бежевой) — не путать
по смыслу, сейчас это всё оттенки фирменного синего. **Никогда не вводи новый цвет** (никакого
`blue-500`, `slate-700` и т.п. из стандартной палитры Tailwind) — только `ink`, `gold`,
`gold-light`, `paper`, плюс `white`/`black` с прозрачностью (`text-white/60`, `bg-ink/5`) и
семантические цвета статусов (`emerald-*` — успех/оплачено, `red-*`/`amber-*` — ошибка/предупреждение).

Шрифт один — Inter, через Google Fonts. Не подключай второй шрифт без явной просьбы.

## 2. Layout

- `.container-page` — единый центрированный контейнер (`max-width: 76rem`, паддинги `1.25rem`).
  Заворачивай в него весь контент страницы, а не изобретай свой `max-w-*`.
- Секции — `<section className="container-page py-12">` (или `py-14`/`py-16` для акцентных
  блоков). Тёмные полноширинные секции — `bg-ink` (иногда с `border-y border-ink/10` сверху/снизу).
- Заголовок страницы — компонент `PageHero` (`src/components/PageHero.tsx`), не пиши свой:
  `eyebrow` (маленькая подпись капсом), `title` (h1), `description`, `dark` (тёмный вариант на
  bg-ink), `wide` (без ограничения ширины у описания), `prototype` (жёлтая плашка «Каркас раздела
  с демо-данными» — ставь только на реально недоделанные разделы).

## 3. Карточки — `.glass` / `.glass-dark`

Фирменный приём сайта — «стеклянная» поверхность с бликом, который следует за курсором
(реализовано в `index.css`, CSS-переменные `--mx`/`--my` двигает `mousemove`-обработчик, ищи
пример в существующих карточках). `.glass` — на светлом фоне, `.glass-dark` — на `bg-ink`.

```tsx
<div className="glass rounded-xl p-5">...</div>       // светлый фон
<div className="glass-dark rounded-xl p-5 text-white"> // тёмный фон (внутри bg-ink секции)
```

Радиус: `rounded-xl` для рядовых карточек в сетке, `rounded-2xl` для крупных акцентных блоков
(герои, модалки, CTA-секции). Не смешивай `rounded-lg`/`rounded-3xl` без причины — в системе
устоялись эти два размера.

Если карточка кликабельная — оборачивай в `<Link>`/`<button>` целиком (`glass block ...`), не
клади отдельную кнопку "Подробнее" внутрь, если можно кликнуть по всей карточке (смотри
`ArticleCard`, `VacancyCard` в `src/components/cards.tsx`).

## 4. Кнопки

Две основные формы, обе `rounded-full` (не `rounded-lg`/`rounded-md` для кнопок-действий):

```tsx
// Основная (тёмная)
<button className="rounded-full bg-ink px-6 py-2.5 text-sm font-semibold text-white hover:bg-ink/90">

// Основная на тёмном фоне (акцентная, светлая)
<button className="rounded-full bg-gold-light px-6 py-2.5 text-sm font-semibold text-ink hover:opacity-90">

// Вторичная / неактивная вкладка
<button className="rounded-full border border-ink/15 px-5 py-2.5 text-sm font-semibold text-ink/60 hover:text-ink">
```

Кнопка с `disabled` во время отправки формы — не прячь её, переключи текст на состояние загрузки
(«Переходим к оплате…») и `disabled:opacity-60`, чтобы не терять место и не дёргать layout.

## 5. Бейджи и теги

```tsx
// Статус-пилюля (маленькая, capsule)
<span className="rounded-full bg-ink/[0.06] px-2.5 py-1 text-xs font-medium text-ink/70">

// Акцентная пилюля (например «Популярный выбор», «Срочно»)
<span className="rounded-full bg-gold-light px-3 py-1 text-xs font-semibold text-ink">

// Специализация/отрасль — готовые компоненты, не переизобретай
import { SpecTag, IndustryTag, TagRow } from '../components/Tag'
```

**Важно про перенос текста в пилюлях**: если текст внутри пилюли — это две смысловые части
(например «590 ₽/мес · выгоднее на 14%»), не оставляй это одной строкой, которая переносится
как попало по ширине контейнера. Разбивай на явные строки через `.split(' · ').map(...)` с
`<span className="block">`, чтобы перенос был предсказуемым и не рвал фразу посередине — это
уже случалось в проекте и выглядело неаккуратно.

## 6. Формы и модалки

- Инпут: `rounded-lg border border-ink/15 px-4 py-2.5 text-sm placeholder:text-ink/40
  focus:border-ink/40 focus:outline-none`.
- Модалка — фиксированный оверлей, снизу на мобиле / по центру на десктопе:
  ```tsx
  <div className="fixed inset-0 z-50 flex items-end justify-center bg-ink/70 p-0 sm:items-center sm:p-4"
       onClick={(e) => { if (e.target === e.currentTarget) close() }}>
    <div className="max-h-[90vh] w-full max-w-md overflow-y-auto rounded-t-2xl bg-white p-6 text-ink sm:rounded-2xl sm:p-8">
      ...
    </div>
  </div>
  ```
  Закрытие по клику на фон (сверять `e.target === e.currentTarget`), не по Escape-хендлеру.
- После сабмита — не просто "успех", а конкретика: зелёный кружок с ✓
  (`bg-emerald-50 text-emerald-600`) + одно предложение, что произошло дальше.
- Если карточки выбора (тарифы, варианты) выстроены в ряд и у них разная длина текста —
  используй `flex flex-col` + `<div className="flex-1" />`-спейсер перед нижним блоком
  (цена/бейдж/кнопка), чтобы кнопки внизу карточек были на одной высоте независимо от того,
  сколько строк текста выше. Без этого спейсера кнопки "плывут" — уже была такая ошибка.

## 7. Sticky-навигация — калибруй, не угадывай

На сайте несколько sticky-элементов друг под другом (шапка `top-0`, под-навигация вкладок
`top-16`, иногда третий уровень — липкая форма сбоку). Смещения (`top-[Npx]`) **нельзя
подбирать на глаз** — высота панели зависит от реального контента и переноса строк.

Правильный процесс:
1. Собери страницу как обычно.
2. Замерь реальную высоту через Playwright:
   `await page.evaluate(() => el.getBoundingClientRect().height)`.
3. Используй сумму реальных высот, а не круглые числа "с запасом".
4. Если панель использует `flex-wrap`, высота непредсказуема (72px на широком экране, 170px
   если перенеслось на 2 строки) — замени на `overflow-x-auto` + `shrink-0 whitespace-nowrap` на
   дочерних кнопках, чтобы высота была гарантированно постоянной, и только потом фиксируй offset.

## 8. Заголовок вкладки браузера

У каждой страницы должен быть свой `document.title`, а не общий "Карьерный Юрист" везде:

```tsx
import { useDocumentTitle } from '../lib/useDocumentTitle'
// статичный заголовок
useDocumentTitle('Маркет')
// динамический — с фоллбэком, если сущность не найдена
useDocumentTitle(vacancy?.title ?? 'Вакансия не найдена')
```

Вызывай в начале компонента, до любых `if (!x) return`, если заголовок зависит от `x` — хук
обязан вызываться безусловно на каждый рендер (правило хуков).

## 9. Реальные счётчики, не демо-числа

Если добавляешь что-то похожее на «N просмотров» / «N откликов» — не генерируй фейковое число
по хэшу id (в проекте так делали раньше и от этого отказались). Смотри `server/lib/vacancyStats.js`
и `server/lib/articleStats.js` как образец: простое файловое хранилище на сервере,
`POST /api/<entity>/:slug/view` инкрементит и возвращает актуальное число, клиентский хук
(`useVacancyStats` в `VacancyDetailBody.tsx`, `useArticleViews` в `src/lib/useArticleViews.ts`,
`useNewsViews`/`useNewsViewCount` в `src/lib/useNewsViews.ts`) дергает его при монтировании.
Если счётчик показывается в списке карточек (не при открытии) — это отдельный **read-only**
GET-эндпоинт, который не инкрементит при каждом рендере списка.

**Ячейка списка vs детальная страница** — если у сущности есть развернутый текст (новость,
статья), карточка в списке остается компактной (тег/бейдж, заголовок, дата, просмотры — без
превью текста, см. `NewsCard` в `cards.tsx`), а полный текст, картинки и прочее — на отдельном
роуте `/news/:slug` (или аналогичном), не разворачивается прямо в списке. Компонент `ArticleBody`
(легкая разметка `## заголовок` / `**акцент**`, абзацы через пустую строку) переиспользуется и
для статей базы знаний, и для новостей — не пиши свой рендерер текста под новую сущность, если
формат тот же.

## 10. Перед тем как считать UI-задачу готовой

1. `npm run build` — 0 ошибок TypeScript.
2. `npm run lint` — 0 предупреждений oxlint.
3. Скриншот через Playwright (Chromium уже установлен, см. паттерн из истории: временный файл
   `.tmp-screenshot*.mjs` в корне репо, `chromium.launch({ executablePath:
   '/opt/pw-browsers/chromium-1194/chrome-linux/chrome', args: ['--no-sandbox'] })`, dev-сервер
   `npm run dev -- --port 5173 --strictPort`) — визуально сверить результат, а не полагаться на
   то, что код "должен" выглядеть правильно.
4. Удалить временные скриншот-скрипты и погасить dev-сервер после проверки.
5. Если менялся сервер (`server/`) — проверить эндпоинт напрямую (`curl`/`node index.js`), не
   полагаться только на то, что фронтенд его вызывает.

## Когда сомневаешься

Если новый паттерн (не описанный выше) нужен впервые — посмотри на 2-3 похожих места в
кодовой базе (`src/components/cards.tsx`, `src/pages/community/CommunityHome.tsx`,
`src/pages/kadry/Candidates.tsx` — самые насыщенные примерами файлы) и следуй их духу, а не
придумывай с нуля. Единообразие важнее личных предпочтений по конкретной кнопке или отступу.
