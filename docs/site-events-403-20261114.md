# Остаточный 403 у /events и проверка текущих форм

По присланному серверному отчёту 14 ноября доступны главная, сообщество,
материалы, кадры, вакансии, маркетплейс, кабинет, контакты, политика и API.
Расчёт трёх тарифов и KQ1111 → 350 ₽ прошёл. Остались HTTP 403 у `/events`
и отрицательный результат счётчика двух форм при 990 сохранённых JS/CSS.
Повторно менять тарифы, оплаты, бот и PDF для исправления этих двух пунктов
не требуется.

## Маршрут мероприятий

В проекте есть публичный каталог `public/events` с обложкой. В nginx
`try_files $uri $uri/ /index.html` проверяет каталог раньше перехода к SPA.
При отсутствии index внутри каталога переход `/events` → `/events/`
может завершиться `directory index ... is forbidden`.

Исправление в `scripts/check-and-repair-site.mjs` применяется только
при локальном HTTP 403 на `/events/`, работающей главной, наличии каталога
без index и **свежей записи именно этого отказа** в журнале nginx.
В загруженном nginx-файле нужного HTTPS-хоста и публичного корня
заменяется только точное правило в `location /`:

```
try_files $uri $uri/ /index.html;
```

на:

```
try_files $uri /index.html;
```

Остальные директивы, ограничения, root, сертификаты, API-location,
содержимое каталога и файлы изображений сохраняются. Неизвестные правила,
alias/proxy в location и недостаток подтверждения останавливают правку.
Все исходные файлы и сведения о правке сохраняются в приватном отчёте
`/root/legalcareerist-bot-backups/site-health-20261114-*`.

Перед применением проверяются неизменность конфигурации и `nginx -t`.
Выполняется reload nginx, без перезапуска API. Проверка ждёт HTTP 200
у `/events`, `/events/`, главной, входного JS, API и существующей обложки.
Если проверка синтаксиса, reload или эти проверки не проходят,
восстанавливаются прежние nginx-файлы и выполняется повторный reload.

## Проверка форм

Предыдущий счётчик ошибочно требовал ровно два файла форм среди **всех**
сохранённых JS. При сохранении старых чанков после публикаций это даёт
ложную ошибку. Новый `currentBundle` идёт от `index.html` и входного JS
по ссылкам модулей и карте зависимостей Vite. Для каждой текущей формы
проверяет её наличие отдельно; сохранённые старые версии не удаляет.
Именно актуальные JS/CSS скачиваются с сайта и сравниваются побайтово.
Отсутствующий текущий чанк нельзя заменить старым при проверке.

Проверки сервера остаются ограниченными: оплаченные заказы и сообщения
не создаются, условия подписок, доступ участников и настройки бота не
изменяются. Отчёт не подтверждает реальную оплату или доставку PDF.
Из облачной среды прямой SSH к серверу по-прежнему недоступен.

сохранность API/данных, старые версии обеих форм, отсутствие нужного JS,
повтор без правок, чужой хост, откат при ошибках синтаксиса/reload/проверки.

по одной актуальной форме CommunityHome и TariffJoinBlock и поле промокода.
