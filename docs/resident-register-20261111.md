# Полная построчная сверка и загрузка реестра, 11 ноября 2026

Входные персональные данные остаются в закрытом артефакте и резервной копии сервера, а не в Git. `subscribers.csv` декодирован как Windows-1251 с разделителем `;`: 71 строка, 66 разных TG ID, 41 договор с обеими активностями «активна», 6 отключений пользователем, 24 отключения менеджером. Повторы TG ID сохраняются как разные банковские строки; ID в колонке `ID` — повторяющийся тарифный план, не Telegram ID и не уникальный профиль человека. Колонки уникального `profile_id` в этом CSV нет.

На трёх скриншотах 76 строк: 23 бесплатные (включая основателя), 8 амбассадоров, 43 платные, 2 служебных аккаунта. Дополнительно сохранены все 10 персональных ориентиров владельца. Все 157 исходных строк имеют отдельный стабильный ключ, попадают в `source-coverage.csv` ровно один раз и связаны с итоговой записью. Это контроль покрытия источников, а не число разных людей или доказательство полного состава Telegram. Ники на изображениях переписаны вручную и без живого ответа Telegram не объявляются актуальными.

## Команды

Только чтение и отчёты:

```sh
node scripts/reconcile-residents.mjs --input /PRIVATE/input-evidence.json --output /PRIVATE/report
```

Локально без PM2/Telegram:

```sh
node scripts/reconcile-residents.mjs --input /PRIVATE/input-evidence.json --output /PRIVATE/report --offline
```

Установка проверенного пакета на фактический runtime основного API:

```sh
node scripts/install-resident-register.mjs --input /PRIVATE/input-evidence.json --packet updates/resident-register --apply
```

Для переданного владельцем набора также собран самодостаточный shell-файл в закрытых артефактах. Он содержит данные и код; Git pull, npm install и ручное указание адресов API для его работы не требуются. Обычный запуск применяет пакет; аргумент `--check` выполняет только чтение. Нужен Node >=20.12 и доступ пользователя сервера к PM2 и его рабочим данным. Базовый код — accf296; неизвестные версии останавливают установку до изменений. Переключать Git-ветку на сервере не нужно.

## Что делает сверка

Читает действующий PM2 runtime, его настройки через существующий безопасный загрузчик, `pending-joins.json`, `bot-users.json`, `prodamus-webhooks.jsonl`; проверяет администратора бота и каждого известного кандидата через `getChatMember`. Методы изменения Telegram не разрешены. Проверяет исходные подписи сохранённых банковских событий доступными ключами, без повторного применения событий. Сопоставляет деньги с точным заказом, датой, суммой, планом и непротиворечивым ID; сохраняет отдельно несопоставленные/неоднозначные события. Все карточки просмотрены, тестовые/демо-карточки исключены из реальных денежных итогов и прав.

Имена не используются как ключ слияния. Контакт из бота с устаревшим ником не становится подтверждённой привязкой нового человека. Один телефон у двух строк скриншота не позволяет назначить им один TG ID. У строки без найденного ника или ID остаётся явный статус неопределённости.

## Что меняет установщик

Сначала сохраняет отчёт и сверяет SHA-256 кода, затем останавливает единственный основной процесс и делает закрытую копию данных в `/root/legalcareerist-bot-backups/resident-register-20261111-*`. Дополняет хранилище отдельными карточками разрешений владельца с детерминированными ключами; существующие денежные карточки не переписывает. Карточки разрешений имеют `paid:false`, пустой `payments`, без `lastPaidAt` и `nextPaymentAt`. Источник, банковские статусы, планы, суммы и расписания хранятся отдельно в `providerSnapshot`. Повтор не создаёт карточки заново.

Для двухсторонне активного CSV доступ владельца ограничен будущей датой из расписания. Эта дата не записывается как подтверждение денег. Бесплатные и амбассадорские разрешения требуют найденного TG ID и свежего совпадения username. Указания по Анастасии и Диане сохраняют отдельные защищённые права. Если человек явно активен в списке владельца, но банковский срок неизвестен/договор отключён, это отдельное разрешение до сверки оплаты, не новое списание и не якобы бесплатный тариф навсегда. После подтверждения текущего оплаченного периода штатная автоматика завершает временное разрешение; бесплатные/амбассадорские права и запрет исключать Диану сохраняются. Повтор этого же импорта не возрождает завершённое разрешение.

Исправлены сопоставления платежей и кабинета: подтверждённый TG ID приоритетнее общего телефона/почты; противоречивые ID и неоднозначный контакт останавливают зачисление. Нельзя защитить просроченного человека действующей карточкой другого TG ID через общий телефон. История событий сохраняется для последующей сверки.

Установщик не запускает прежние установщики, восстановление оплат, повтор вебхуков, рассылки, напоминания или операции с договорами Prodamus. Он не создаёт очереди сообщений или приглашений, не меняет политику исключений, окружение или платёжные ключи. После установки перезапускается основной API с его прежним обычным рабочим циклом. Проверяется здоровье API и сохранность параметров автоматики. При ошибке код откатывается; старую финансовую базу поверх новых поступивших событий не восстанавливает.

## Обнаруженные расхождения

Персональные расхождения сохранены в закрытом `exceptions.csv`: отличающиеся Telegram ID между прежними указаниями и CSV, разные username у одноимённых записей, общий телефон двух людей, расхождения номинальной цены и активного плана, недопустимые символы в транскрипции username. Числовые идентификаторы, телефоны и персональные строки выгрузки в Git не включаются. Временный допуск по списку владельца хранится отдельно от подтверждения денег.

## Проверки

170 модульных проверок; HTTP-сценарии: 20 полного цикла подписки, 16 восстановления доступа, 25 автоматики. Внешние сервисы во всех тестах синтетические. Отдельная изолированная проверка реального установщика: чтение без изменений, отказ на неизвестном коде, применение, повтор без дублей, отказ при отсутствующем хранилище, сохранность денег, запрет сообщений и отсутствие вывода токенов. Проверены реальные функции хранилища при конфликте ID/общем телефоне и кабинета при общей почте. Контроль реальных входных данных: 157 из 157 ключей сохранены ровно один раз.

В этой среде нет установленного доступа к Timeweb, поэтому установка и свежая проверка реальных участников здесь не объявляются выполненными. Локальный результат содержит все предоставленные данные; серверный запуск дополнит его текущими username, присутствием и денежной историей. Полноту состава Telegram нельзя доказать одним Bot API: он не позволяет перечислить всех участников группы.
