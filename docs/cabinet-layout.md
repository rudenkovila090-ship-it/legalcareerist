# Кабинет: единый профиль и навигация

Профиль и управление аккаунтом собраны в левой карточке на всех страницах кабинета. На главной сначала четыре плитки, затем новости и свёрнутый перечень разделов. Выход расположен под меню. Статус амбассадора показывается только при совпадении связанного Telegram с реестром амбассадоров; права доступа к платным разделам определяются прежними проверками подписки.

Вакансии и карьера используют один компонент ProfessionalProfile и прежний `/api/account/profile`. Старые адреса практик, ожиданий, документов и конфиденциальности открывают профиль внутри карьеры. Из вакансий доступен `/cabinet/job-profile`, из карьеры — `/cabinet/career-profile`. Дополнительного заполнения нет.

База знаний остаётся внутри общего кабинета. Поиск по названию, раздел, отметки читателя и сортировка расположены над материалами. Полнотекстовый поиск остаётся доступен через Ctrl K. При входе показывается список, выбранная статья открывается ниже. Прежние прямые ссылки `?p=...` работают.

## Контакты и почта

`networking` — новая часть серверного профиля: intro, contacts, version. До 250 контактов, поля проверяются и ограничены на сервере. Чужой login из тела запроса не используется: владелец определяется сессией. После изменений версия увеличивается; устаревшая версия возвращает `profile_conflict`. Удаление и экспорт профиля охватывают эту часть. Записная книжка принадлежит аккаунту: пользователи общего демо видят общую демо-книжку.

Почта для связи меняется отдельно от адреса входа. Новый адрес подтверждается восьмизначным кодом, живущим 10 минут, с пятью попытками. На сервере хранится хеш кода. Отправка требует текущий пароль и ограничена по частоте. Адрес входа и привязки к оплаченным подпискам сохраняются. При отсутствии SMTP показывается ошибка; успешная отправка не имитируется.

Общий демо-аккаунт сохраняет блокировку смены контактов для входа, пароля, Telegram и почты. Записная книжка сохраняется в его изолированном хранилище. Тесты не отправляют реальные письма: доставка проверяется подставным отправителем.

## Проверки

- `npm run build`
- `node server/tests/cabinet-profile.mjs`: HTTP CRUD, согласия, изоляция аккаунтов, конфликт версий, подтверждение почты и неизменность финансовой истории.
- `node server/tests/resident-demo.mjs`: 28 проверок изоляции демо.
- `python scripts/tests/cabinet-browser.py` (при запущенных `node server/tests/cabinet-profile.mjs --serve` и `npm run dev -- --host 127.0.0.1 --port 4196`): разделы кабинета, фильтры, сохранение/редактирование/удаление контактов, единая форма карьеры и вакансий, ширины 320/390/768/1440 px.

Для установки требуется обновить фронтенд и серверные модули accountStore, accountUsers, accountProfile, accountEmail, residentDemo и регистрацию маршрутов accountEmail в index.js. Нужно обновлять действующие изолированные runtime основного API и демо, обнаруживая их через PM2. Старые установщики UI содержат прежние контрольные суммы и для этих изменений не подходят. Финансовые модули, действующие платежи и настройки исключения не меняются.
