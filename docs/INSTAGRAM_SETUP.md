# Подключение Instagram к @LegalcareeristBot

## Что получится

```
Instagram (комментарии, личные сообщения)
        │  вебхуки Meta
        ▼
  Мост (этот репозиторий, FastAPI)  ──►  Instagram API: личные ответы, ответы на комментарии
        │
        ▼
  @LegalcareeristBot  ──►  чат менеджеров в Telegram: готовые заявки и пересланные сообщения
```

Три сценария из `config/flows.json`:

1. **Комментарий с ключевым словом → DM.** Под постом: «Напишите КОНСУЛЬТАЦИЯ». Человек комментирует, мост отправляет ему личное сообщение со ссылкой (бот, сайт, оплата) или первым вопросом квалификации и отвечает в комментариях «Отправили в директ 📩».
2. **Автоответы и квалификация в DM.** Меню → 3–4 вопроса по сегменту (клиент, работодатель, кандидат, сообщество). Слово «менеджер» в любой момент зовёт человека.
3. **Заявка менеджеру в Telegram.** Готовая заявка и все сообщения, пока диалог ведёт менеджер, приходят карточкой в рабочий чат. Заявки дополнительно сохраняются в SQLite на случай сбоя Telegram.

Мост использует токен бота **только для `sendMessage`** и не читает обновления (`getUpdates`/webhook). Уже работающий бот не затрагивается.

## Что нужно заранее

| Что | Зачем |
|---|---|
| Instagram-аккаунт типа **Business или Creator** | Messaging API работает только с профессиональными аккаунтами (Настройки → Тип аккаунта → Переключиться на профессиональный) |
| Аккаунт разработчика на [developers.facebook.com](https://developers.facebook.com) | Создание приложения Meta |
| Хостинг с публичным **HTTPS** и постоянным диском | Meta шлёт вебхуки на ваш URL; на диске лежат диалоги и свежий токен |
| Рабочий чат менеджеров в Telegram | Сюда приходят заявки |

## Шаг 1. Приложение Meta

1. [developers.facebook.com/apps](https://developers.facebook.com/apps) → **Create app** → тип **Business**.
2. В приложении: **Add product → Instagram → API setup with Instagram login**.
3. **App settings → Basic** → скопируйте **App Secret** → это `IG_APP_SECRET`.

## Шаг 2. Привязать аккаунт и выпустить токен

1. На странице **API setup with Instagram login** → блок *Generate access tokens* → **Add account** → войдите в Instagram-аккаунт компании.
   Если аккаунт не принадлежит вашему профилю разработчика: **App roles → Roles → Add people → Instagram Testers**, затем в Instagram примите приглашение (Настройки → Приложения и сайты → Приглашения тестера).
2. Нажмите **Generate token** и скопируйте токен → это `IG_ACCESS_TOKEN`. ID аккаунта рядом с токеном → это `IG_ACCOUNT_ID`.
3. Придумайте длинную случайную строку, например `openssl rand -hex 24` → это `IG_VERIFY_TOKEN`.

Токен живёт 60 дней. Мост сам продлевает его каждые 30 дней и хранит свежий в БД; если продлить не удаётся 3 проверки подряд, в чат менеджеров придёт предупреждение.

## Шаг 3. Telegram

1. Токен бота из BotFather → `TELEGRAM_BOT_TOKEN`.
2. Создайте группу менеджеров, добавьте в неё @LegalcareeristBot.
3. Узнайте ID группы: добавьте на минуту @RawDataBot (или @getidsbot) и напишите любое сообщение, ID вида `-100…` → `TELEGRAM_MANAGER_CHAT_ID`, затем удалите вспомогательного бота. Не используйте `getUpdates` самого @LegalcareeristBot: он конфликтует с работающим ботом.
4. Проверка: `curl "https://api.telegram.org/bot<TOKEN>/sendMessage" -d chat_id=<ID> -d text=проверка`.

## Шаг 4. Деплой моста

Локальная проверка:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest                      # 48 тестов, без доступа к Meta
cp .env.example .env        # заполните значения
set -a; . ./.env; set +a
uvicorn bridge.app:create_app_from_env --factory --port 8000
```

Продакшн: любой хостинг с Docker (Fly.io, Railway, Render, свой VPS).

```bash
docker build -t legalcareerist-bridge .
docker run -d --restart=always -p 8000:8000 -v bridge-data:/data --env-file .env legalcareerist-bridge
```

Обязательно: переменные из `.env.example`, **постоянный диск на `/data`** (иначе после перезапуска потеряются состояния диалогов и продлённый токен), HTTPS перед сервисом. Проверка: `https://<ваш-домен>/health` отвечает `{"ok":true,…}`.

Ссылки в текстах: `BOT_URL` (по умолчанию `https://t.me/LegalcareeristBot`), `SITE_URL`, `PAYMENT_URL`. Правила, которым нужна незаданная ссылка (`оплата`, `сайт`), отключаются автоматически, и в логах будет предупреждение.

## Шаг 5. Вебхуки

1. В Meta: **API setup with Instagram login → Configure webhooks**.
2. **Callback URL**: `https://<ваш-домен>/webhook/instagram`, **Verify token**: значение `IG_VERIFY_TOKEN` → **Verify and save**. Мост отвечает на проверку сам.
3. Подпишитесь на поля **`comments`** и **`messages`**.
4. Подпишите приложение на аккаунт (в панели есть переключатель, либо запросом):

```bash
curl -X POST "https://graph.instagram.com/v23.0/me/subscribed_apps" \
  -d "subscribed_fields=comments,messages" \
  -H "Authorization: Bearer $IG_ACCESS_TOKEN"
```

## Шаг 6. Тест в режиме разработки

Пока приложение в режиме *Development*, вебхуки приходят только от пользователей с ролью в приложении (владелец, Tester).

1. С тестового аккаунта оставьте под постом комментарий `консультация`. Должны прийти личное сообщение с первым вопросом и публичный ответ «Отправили в директ».
2. Ответьте на вопросы. В Telegram придёт карточка «🆕 Новая заявка из Instagram».
3. Напишите в DM слово `менеджер`: бот замолчит на `HUMAN_MODE_HOURS`, дальнейшие сообщения будут пересылаться в Telegram.
4. Не приходит ничего: смотрите логи моста и **Meta → Webhooks → Recent deliveries**.

## Шаг 7. Выход в боевой режим (самое долгое)

Чтобы бот работал для всех, а не только для людей с ролью, нужен **Advanced Access** через App Review:

- Права: `instagram_business_basic`, `instagram_business_manage_messages`, `instagram_business_manage_comments`.
- Для каждого права Meta просит скринкаст (короткое видео работы сценария) и описание, зачем оно нужно.
- В настройках приложения нужны **Privacy Policy URL** и (по запросу) инструкция по удалению данных. Политика обязана говорить о сборе контактов в Instagram и передаче менеджерам, согласуйте её с юристом.
- Для Advanced Access может потребоваться **Business Verification** (документы юрлица). Доступность зависит от страны регистрации компании, проверьте это заранее.
- После одобрения переключите приложение в **Live**.

Рекомендуем начать подготовку заранее: проверка занимает дни и может уходить на доработку.

## Как менять сценарии

Тексты, ключевые слова и вопросы лежат в `config/flows.json`, программист не нужен (после правки перезапустите сервис).

- `comment_rules[].keywords` — слова-триггеры. Выбирайте **уникальные призывы** («КОНСУЛЬТАЦИЯ», «ВАКАНСИИ»), а не частые слова: иначе бот будет отвечать на любые комментарии. `слово*` — совпадение по началу слова.
- `comment_rules[].media_ids` — привязать правило к конкретным постам (ID поста; пусто = любые посты).
- `comment_rules[].start` — что делать после первого сообщения: ключ сегмента (`client`, `employer`, …), `"menu"` или `null` (просто отправить текст).
- `public_replies` — несколько вариантов публичного ответа: одинаковые ответы под десятками комментариев Instagram может счесть спамом.
- `segments[].questions` — вопросы квалификации; можно добавлять и менять.
- Плейсхолдеры в текстах: `{bot_url}`, `{site_url}`, `{payment_url}`. Для атрибуции можно писать `{bot_url}?start=ig_vakansii`.
- Личный ответ на комментарий должен помещаться в ~900 байт (около 450 символов кириллицы); сервис не запустится, если текст длиннее.

## Правила Instagram, которые учтены в коде

- **Private reply** (личный ответ на комментарий): одно сообщение в течение 7 дней после комментария; дальше диалог продолжается, только если человек ответил.
- **Окно 24 часа**: писать в DM можно в течение 24 часов после последнего сообщения человека.
- Лимит текста DM — 1000 байт; длинные тексты мост режет на части.
- Дубликаты вебхуков отбрасываются; собственные комментарии и эхо своих сообщений игнорируются (нет петель).
- Человек может отказаться словом `стоп` и позвать менеджера словом `менеджер`: автоматизация без выхода к человеку нарушает правила платформы и раздражает клиентов.

## Безопасность

- Секреты (`IG_ACCESS_TOKEN`, `IG_APP_SECRET`, `TELEGRAM_BOT_TOKEN`) только в переменных окружения хостинга; `.env` в git не попадает. Если секрет попал в чат, скриншот или репозиторий, перевыпустите его: App Secret и токен в Meta, токен бота через `/revoke` в BotFather.
- Мост принимает вебхуки только с верной подписью `X-Hub-Signature-256` (HMAC от App Secret) и не пишет токены в логи.
- Вы собираете персональные данные (имя, контакты, описание ситуации): добавьте в первый вопрос квалификации ссылку на политику обработки данных и согласие.

## Что проверено, а что нет

Проверено автотестами и запуском сервера: подпись и verify-token вебхука, разбор комментариев и сообщений, сценарии диалога, формат запросов к Graph API, продление токена, экранирование текста в карточках Telegram.

**Не проверено вживую**: реальные вызовы Meta и Telegram. Их можно сделать только с вашими токенами. Поэтому первый прогон на шаге 6 обязателен. Версия API (`GRAPH_API_VERSION`, по умолчанию `v23.0`) и названия кнопок в панели Meta со временем меняются: сверяйтесь с [документацией Instagram Platform](https://developers.facebook.com/docs/instagram-platform).

## Что можно добавить дальше

- Ответ менеджера из Telegram прямо в Instagram DM (reply на карточку → отправка клиенту).
- Выгрузка заявок в Google Sheets или CRM (таблица `leads` в SQLite уже есть).
- Быстрые кнопки (quick replies) вместо ответа цифрой.
- Реакции на упоминания в Stories и рассылка по подписчикам с согласием на рассылку.
