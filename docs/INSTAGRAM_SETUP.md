# Бот в Instagram: подключение

Человек пишет в Instagram, бот отвечает ему там же: на комментарий с ключевым словом отправляет личное сообщение, в директе ведёт по вопросам, при слове «менеджер» зовёт человека. Готовая заявка приходит менеджерам в Telegram, и **менеджер отвечает на карточку прямо в Telegram, а клиент получает ответ в Instagram**.

```
Instagram (комментарии, личные сообщения)
        │ вебхуки Meta                      ▲ личные ответы, ответы на комментарии
        ▼                                   │
  Мост (этот репозиторий, FastAPI) ──────────┘
        │
        ▼
  @LegalcareeristBot ──► группа менеджеров в Telegram: заявки, пересланные сообщения;
                          ответ менеджера на карточку уходит клиенту в Instagram DM
```

Сценарии (тексты и ключевые слова в `config/flows.json`):
1. **Комментарий с ключевым словом → личное сообщение** со ссылкой (бот, сайт, оплата) или первым вопросом; под комментарием публикуется один из вариантов «Отправили в директ 📩».
2. **Директ:** меню, 2–3 вопроса по сегменту (клиент, работодатель, кандидат, сообщество), «менеджер» зовёт человека, «стоп» отключает автоответы.
3. **Заявка менеджерам в Telegram.** Ответ на карточку уходит клиенту.

## Что уже сделано (по ходу подключения)
- Приложение Meta создано от Facebook-профиля с аккаунтом разработчика; сценарий «Управление сообщениями и контентом в Instagram»; разрешения `instagram_business_basic`, `instagram_business_manage_comments`, `instagram_business_manage_messages` добавлены.
- Instagram-аккаунт добавлен в приложение ролью «Тестировщик Instagram», приглашение принято, токен создан.

## Что осталось

### 1. Сохранить секреты (в менеджер паролей, не в чат и не в git)
| Значение | Где взять | Переменная |
|---|---|---|
| ID аккаунта | «Настройка API для входа в Instagram» → блок «Сгенерируйте маркеры доступа», число под именем аккаунта | `IG_ACCOUNT_ID` |
| Токен | там же, «Сгенерировать маркер» (показывается один раз; потеряли — создайте новый) | `IG_ACCESS_TOKEN` |
| Секрет Instagram-приложения | вверху той же страницы («Показать»; если засветили, «Сбросить») | часть `IG_APP_SECRET` |
| Секрет приложения Meta | Настройки приложения → Основное | часть `IG_APP_SECRET` |
| Токен проверки вебхука | придумайте сами: `openssl rand -hex 24` | `IG_VERIFY_TOKEN` |

Какой из двух секретов Meta использует для подписи вебхуков, определить заранее нельзя, поэтому в `IG_APP_SECRET` укажите оба через запятую: `секрет1,секрет2`.

Токен живёт 60 дней. Мост сам продлевает его и хранит свежий в базе; если продлить не удаётся 3 проверки подряд, в группу менеджеров придёт предупреждение.

### 2. Telegram
- Токен из BotFather → `TELEGRAM_BOT_TOKEN`. Группа менеджеров с добавленным ботом → её ID `-100…` в `TELEGRAM_MANAGER_CHAT_ID`. ID узнаёте командой `python -m bridge.tgbot --find-chat` (подробно в [TELEGRAM_BOT.md](TELEGRAM_BOT.md)).
- **Важно:** у одного токена может быть только один «слушатель». Мост опрашивает Telegram (для ответов менеджеров). Если @LegalcareeristBot уже работает где-то ещё, остановите тот процесс. Иначе боты будут мешать друг другу. Если у бота включён webhook, мост отключит опрос и напишет об этом в логе.

### 3. Сервер
Нужен сервер **за пределами РФ** (мост обращается к `graph.instagram.com`, который из РФ, скорее всего, недоступен) с публичным IP, Ubuntu 22.04/24.04, от 1 vCPU и 1 ГБ RAM, и открытыми портами 80 и 443. Оплату выбирайте по своим возможностям, условия проверьте сами.

Адрес для HTTPS (`DOMAIN`):
- свой домен: добавьте A-запись на IP сервера, либо
- без покупки домена: `<IP с дефисами>.sslip.io`, например для `203.0.113.10` это `203-0-113-10.sslip.io`. Он указывает на тот же IP, сертификат Caddy получит сам. Это обходной путь: если сертификат не выдаётся, возьмите свой домен.

```bash
# на сервере
curl -fsSL https://get.docker.com | sh
git clone -b claude/magical-pasteur-r0fe1j <адрес репозитория> legalcareerist && cd legalcareerist
cp .env.example .env && nano .env        # заполните значения (DOMAIN, IG_*, TELEGRAM_*, PRIVACY_URL)
docker compose up -d --build
docker compose logs -f app               # смотрите логи
```

Проверка: `https://<DOMAIN>/health` отвечает `{"ok":true,…}`. Затем на своём компьютере (со значениями `.env`) запустите самопроверку:

```bash
python -m bridge.doctor --url https://<DOMAIN>
```

Скрипт проверит токен, ID аккаунта, тип аккаунта, подписки на вебхуки, Telegram и совпадение verify token. Отчёт не содержит секретов, его можно присылать целиком.

Сборку Docker-образа и `docker-compose.yml` я в разработке не проверял (в среде нет Docker): первый запуск начните с `docker compose logs`.

### 4. Вебхук в Meta
В панели приложения: Сценарии использования → Instagram → «Настройка API для входа в Instagram»:
1. **Настройка Webhooks** (блок 3): **URL обратного вызова** `https://<DOMAIN>/webhook/instagram`, **токен проверки** = ваш `IG_VERIFY_TOKEN` → «Проверить и сохранить». Мост отвечает на проверку сам.
2. Подпишитесь на поля **`comments`** и **`messages`**.
3. В блоке 2 включите переключатель **«Подписка на Webhooks»** у аккаунта (либо `python -m bridge.doctor --subscribe`).

### 5. Тест в режиме разработки
Пока приложение не опубликовано, вебхуки приходят только от людей с ролью в приложении. Для теста:
- добавьте **второй (тестовый) Instagram-аккаунт** как «Тестировщик Instagram» (Роли в приложении → Добавить людей) и примите приглашение в его настройках («Приложения и сайты»);
- с него оставьте под постом @legalcareerist комментарий `консультация`. Должны прийти личное сообщение с первым вопросом и публичный ответ «Отправили в директ»;
- ответьте на вопросы: в Telegram придёт карточка «Новая заявка из Instagram»;
- **ответьте на карточку в Telegram:** ответ должен прийти тестовому аккаунту в директ. Instagram разрешает писать в течение 24 часов после последнего сообщения клиента;
- напишите в директ «менеджер»: бот замолчит на `HUMAN_MODE_HOURS`.

Не приходит ничего: логи (`docker compose logs app`) и в Meta → Webhooks → «Недавние доставки».

### 6. Боевой режим (самое долгое)
Чтобы бот работал для всех, а не только для людей с ролью, нужен **Advanced Access** через проверку приложения (App Review):
- права `instagram_business_basic`, `instagram_business_manage_messages`, `instagram_business_manage_comments`: для каждого скринкаст (короткое видео сценария) и описание, зачем он нужен;
- **Privacy Policy URL** в настройках приложения (политика обработки данных, согласуйте с юристом);
- как правило, **проверка компании** (Business Verification) для портфолио «Карьерный юрист»; в панели приложения компания помечена «не подтверждена». Доступность проверки зависит от страны регистрации компании, проверьте её заранее;
- после одобрения переключите приложение в **Live**.

Начинайте подготовку заранее: проверка занимает дни и может уходить на доработку.

## Как менять сценарии
Тексты, ключевые слова и вопросы лежат в `config/flows.json` (после правки перезапустите сервис: `docker compose restart app`).
- `comment_rules[].keywords`: слова-триггеры. Выбирайте **уникальные призывы** («КОНСУЛЬТАЦИЯ», «ВАКАНСИИ»), а не частые слова: иначе бот ответит на любые комментарии. `слово*`: совпадение по началу слова.
- `comment_rules[].media_ids`: привязать правило к конкретным постам (пусто: любые).
- `comment_rules[].start`: ключ сегмента (`client`, `employer`, …), `"menu"` или `null` (просто отправить текст).
- `public_replies`: несколько вариантов публичного ответа (одинаковые ответы под десятками комментариев Instagram может счесть спамом).
- Плейсхолдеры в текстах: `{bot_url}`, `{site_url}`, `{payment_url}`, `{privacy_url}`. Правила, которым нужна незаданная ссылка, отключаются автоматически с предупреждением в логе.
- Личный ответ на комментарий должен помещаться в ~900 байт (около 450 символов кириллицы), иначе сервис не запустится.

## Правила Instagram, учтённые в коде
- **Private reply** (личный ответ на комментарий): одно сообщение в течение 7 дней после комментария; дальше диалог идёт, только если человек ответил.
- **Окно 24 часа** для обычных сообщений; ответ менеджера вне окна не доставится, менеджер увидит понятную ошибку.
- Лимит текста DM около 1000 байт; длинное режется на части.
- Дубли вебхуков отбрасываются; собственные комментарии и эхо игнорируются (нет петель).
- Человек может отказаться словом `стоп` и позвать менеджера словом `менеджер`.

## Безопасность
- Секреты только в `.env` на сервере и менеджере паролей, `.env` в git не попадает. Засветили секрет или токен в чате или на скриншоте: перевыпустите (секрет «Сбросить» в Meta, токен «Сгенерировать маркер», токен бота `/revoke` в BotFather).
- Мост принимает вебхуки только с верной подписью `X-Hub-Signature-256` и не пишет токены в логи. Снаружи Caddy открывает только `/webhook/instagram` и `/health`.
- Вы собираете персональные данные: задайте `PRIVACY_URL`, тогда бот запросит согласие до сбора контактов. Не расширяйте вопросы до подробностей дел.

## Что проверено, а что нет
Проверено автотестами (97) и запуском настоящего сервера: подпись и verify token, оба секрета, разбор комментариев и сообщений, сценарии, формат запросов к Graph API, продление токена, карточки и ответ менеджера в Instagram, экранирование текста.

**Не проверено вживую:** реальные вызовы Meta и Telegram, Docker-образ и Compose. Их можно проверить только на вашем сервере и с вашими токенами: используйте `python -m bridge.doctor`. Версия API (`GRAPH_API_VERSION`, по умолчанию `v23.0`) и названия кнопок в панели Meta со временем меняются: сверяйтесь с [документацией Instagram Platform](https://developers.facebook.com/docs/instagram-platform).
