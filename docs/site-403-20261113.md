# Проверка сайта при nginx 403

Дополнение 14 ноября: [устранение отказа `/events` и проверка текущих форм](site-events-403-20261114.md).

Скриншот с `403 Forbidden / nginx/1.24.0 (Ubuntu)` подтверждает отказ nginx,
но не определяет его причину. Прямой запрос из облачной среды отклонён
сетевым прокси (`CONNECT 403`, `envoy`); это другой ответ. SSH, серверные
переменные и `/var/www/legalcareerist` в облачной среде отсутствуют.

В публикации исправлен дефект прав: `publishStatic` теперь задаёт публичные
права самому корню сайта и файлам с неизменившимся содержимым. Ранее
`dist` с правами 0700 и `index.html` с 0600 могли остаться закрытыми после
сборки с `umask 077`. Это воспроизводимый дефект, а не подтверждение
конкретной причины на работающем сервере.

## Команда проверки

`scripts/check-and-repair-site.mjs` запускается от root на сервере сайта.
Требует существующие Node.js, nginx, PM2, curl и runuser. Пакет не нужно
устанавливать через npm, сайт не пересобирается. Архивировать следует:

```
scripts/check-and-repair-site.mjs
scripts/repair-community-promo-static.mjs
scripts/lib/site-static-access.mjs
scripts/lib/bot-runtime-settings.mjs
scripts/lib/site-bundle.mjs
scripts/lib/nginx-spa-routing.mjs
```

Команда читает `nginx -t/-T`, определяет HTTPS-корень нужного виртуального
хоста, проверяет ответ локального nginx с правильными Host/SNI и проверкой
сертификата. До изменения прав подтверждает структуру публичной сборки;
каталоги приложения, закрытые файлы, символические и жёсткие ссылки
останавливают исправление. Меняет права только внутри публичной сборки
при выявленном отказе доступа. Для закрытого родительского каталога
предоставляет пользователю nginx только необходимый проход через ACL,
сохраняя маски чтения/записи. Без установленного пакета `acl` сообщает
конкретный недоступный родительский каталог, не раскрывая его всем.
Прежние права/ACL и результаты сохраняются в приватном каталоге
`/root/legalcareerist-bot-backups/site-health-20261114-*` (у первого запуска — `20261113`).

Проверяет URL сайта, включая `/events` и `/events/`, обложку,
побайтовое совпадение JS/CSS текущей сборки, наличие обеих актуальных
форм сообщества и поля промокода,
локальный/публичный API, расчёт трёх тарифов и KQ1111 → 350 ₽ / месяц /
план 2611878. Проверяет процесс PM2, JSON-хранилища, обработчик и очередь
адаптации, SHA-256 PDF владельца, Telegram getMe/getWebhookInfo и права
бота в сообществе. Секреты, карточки участников и полные журналы не печатает.

Без перезапусков API, правок бота, изменений оплат, вступлений,
исключений, сообщений или создания платёжных ссылок. Единственный POST
на сайт — чистый расчёт `/api/community/promo`. Проверки Telegram только
читают состояние. Реальные списания, отправка PDF и фактическая работа
polling этой командой не подтверждаются. С 14 ноября при подтверждённой
журналом коллизии каталога `/events` точечно исправляет SPA fallback nginx,
проверяет конфигурацию, выполняет reload и откат при неудаче. Правила `deny`, неверный root/index,
неработающий API и ошибки внешних сервисов выводятся как конкретные
непрошедшие проверки; скрипт не заменяет конфигурацию вслепую.

`SITE_CHECK_PASSED` означает прохождение перечисленных проверок.
При любом непрошедшем пункте выводится `SITE_CHECK_INCOMPLETE` и код 1.

## Проверки изменения

```
node --test scripts/tests/site-static-access.test.mjs scripts/tests/community-promo-static.test.mjs
python3 scripts/tests/community-promo-publication.py
python3 scripts/tests/site-health-repair.py
```

В интеграционной проверке сервисы подменены: воспроизводятся 403 из-за
прав, повтор без изменений, запрет конфигурацией, отсутствующий lazy JS
и чужой виртуальный хост. В непривилегированной облачной среде отдельный
пользователь nginx моделируется через реальные Unix mode bits временных
файлов. На root проверка использует настоящий runuser. Для проверки
успешного результата со всеми пунктами локально дополнительно передан
`SITE_TEST_QUEST_PDF` с присланным владельцем PDF. В Git PDF не добавляется.
