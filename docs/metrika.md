# Яндекс Метрика

Счётчик **113667773** (номер из кода, присланного 18.10.2026; на более раннем скриншоте был 113667705 — если нужен тот, поменяйте `METRIKA_ID` в `src/lib/metrika.ts`).

## Что стоит на сайте
- Код счётчика запускается из корня приложения (`src/components/MetrikaTracker.tsx`), поэтому он работает на всех страницах сайта. В статическом `index.html` его нет сознательно: **счётчик загружается только после нажатия «Принять»** в окне про cookie (`src/components/CookieBanner.tsx`). Выбор запоминается в браузере (`localStorage`, ключ `ky_cookie_consent`); изменить его можно ссылкой «Настройки cookie» в подвале. Отказ после согласия удаляет cookie `_ym*` и перезагружает страницу.
- Включены вебвизор, карта кликов, отслеживание внешних ссылок, точный показатель отказов. Вебвизор включён только при согласии посетителя; **то, что люди набирают в полях, и содержимое личного кабинета в запись не попадают** (`ym-disable-keys` на корне и на всех полях ввода, `ym-hide-content` на кабинете). Выключить вебвизор целиком: `WEBVISOR = false` в `src/lib/metrika.ts`.
- Сайт — одностраничное приложение, поэтому при каждом переходе отправляется просмотр `ym(113667773, 'hit', адрес)` (первый просмотр учитывает сам счётчик, без дублей). Адреса очищаются от служебных параметров (в них бывают токены покупок), остаются `utm_*`, `yclid`, `ysclid`. Раздел `/cabinet` в просмотры не отправляется.
- Пиксель `<noscript>` не ставится: он считал бы посетителей без согласия.
- **Персональные данные (имена, телефоны, почта) в цели и параметры не передаются никогда.**

## Цели
Все цели — типа **«JavaScript-событие»**. Идентификатор цели в Метрике — это название из таблиц ниже. Отправка идёт функцией `goal(name, params?, callback?)` (`src/lib/metrika.ts`); без согласия на cookie она ничего не отправляет.

### Заявки (после успешного ответа сервера, не по клику)
| Цель | Где срабатывает |
|---|---|
| `lead_employer` | три формы работодателя на `/kadry`: «Найти сотрудника», «Заявка на кандидатов», заказ услуги из калькулятора (в параметре `form` — тип формы) |
| `lead_consult` | заказ консультации («Заказать»); форма «Отправить вопрос» не считается |
| `lead_reserve` | обе формы кадрового резерва |
| `lead_community` | после ответа `/api/community/subscribe` (заявка создана, ссылка на оплату выдана), перед переходом на оплату |
| `lead_vacancy` | отклик на вакансию |

Заявка считается, когда сервер ответил успешно (`/api/notify` вернул 200). Если сервер недоступен или ответил ошибкой, цели нет.

### Оплаты (после подтверждения оплаты сервером, один раз на заказ)
| Цель | Параметры | Где срабатывает |
|---|---|---|
| `pay_community` | `order_price` (сумма в рублях), `currency: 'RUB'` | страница `/community/success` |
| `pay_ticket` | то же | страница мероприятия после возврата с оплаты (`?paid=1&t=…`) |
| `pay_product` | то же | страница `/materials/thanks` |

Оплата подтверждается не адресной строкой (`?paid=1` может дописать кто угодно), а сервером: страница опрашивает `GET /api/payment/status`, который отвечает «оплачено» только после подписанного уведомления Prodamus и отдаёт сумму оплаты. Уведомление Prodamus иногда приходит на несколько секунд позже возврата человека на сайт, поэтому страница опрашивает сервер каждые 3 секунды до двух минут. Повторы исключены: номер заказа запоминается в `localStorage` (`ky_goal_pay_…`), перезагрузка страницы и вторая вкладка цель не дублируют. Код: `src/lib/paymentGoal.ts`, сервер — `server/index.js`.

### Клики по кнопкам
У ключевых кнопок есть уникальные `id`; клик по любой кнопке с `id` вида `btn-…` отправляет цель `click_<имя>` (имя — `id` без `btn-`, дефисы заменены на `_`). Клик считается и тогда, когда форма не отправилась из-за незаполненного поля.

| Цель | Кнопка |
|---|---|
| `click_employer_submit` | `/kadry`, форма «Найти сотрудника» (`#btn-employer-submit`) |
| `click_consult_submit` | окно заказа консультации, «Заказать» (`#btn-consult-submit`) |
| `click_reserve_submit` | `/kadry/candidates/reserve`, «Вступить в кадровый резерв» (`#btn-reserve-submit`) |
| `click_community_join` | окно подписки, «Перейти к оплате» (`#btn-community-join`) |
| `click_ticket_buy` | страница мероприятия, «Приобрести билет — …» (`#btn-ticket-buy`) |
| `click_product_buy` | страница материала, «Оплатить и получить доступ» (`#btn-product-buy`) |
| `click_vacancy_apply` | форма отклика на вакансию (`#btn-vacancy-apply`) |

Дополнительные кнопки (по ним тоже уходят цели): `click_employer_candidates_submit`, `click_employer_order_submit`, `click_consult_question_submit`, `click_reserve_request_submit`, `click_product_pay`.

Визуальный выбор кнопки в редакторе Метрики («Клик по кнопке» → «Перейти и выбрать кнопку») может не открыть сайт: счётчик на сайте включается только после согласия, а редактор баннер не принимает. Поэтому цели по кликам — «JavaScript-событие».

## Что учесть
- Кнопка «Проверить счётчик» в Метрике может не найти код: он появляется на странице только после согласия посетителя. Проверять надёжнее так: открыть сайт, нажать «Принять», подождать минуту и посмотреть «Отчёты → Посещаемость» или «Онлайн».
- В статистику попадают только согласившиеся посетители, поэтому цифры будут меньше реальных.
- В Политике (п. 6.20 и раздел 7) нужно описать Метрику: cookie, вебвизор, получатель — ООО «Яндекс», какие данные передаются. Сейчас п. 6.20 говорит, что cookie сайт не использует.
