
ТЗ: приложение-трекер целей по методу «12-недельного года»
1. Назначение
Личное веб-приложение (или desktop, на усмотрение реализации) для ежедневного/еженедельного ввода задач и результатов работы по трём бизнес-целям, с автоматическим расчётом, приближают ли действия пользователя к целям, и сигнализацией о рисках отставания.
Стек на выбор Claude Code: рекомендуется Python (FastAPI/Flask) + SQLite для простоты локального использования, либо простое SPA (React/Vue) с локальным хранением, если нужен более быстрый MVP. Выбор стека — на усмотрение реализации, если соблюдены функциональные требования ниже.

3. Функциональные требования
3.1. Ввод данных
Форма быстрого добавления задачи: название, направление, цель, неделя, приоритет, тип связи с целью.
Форма ежедневного отчёта: список задач на сегодня со статусами (выполнено/не выполнено/частично), свободное текстовое поле «что сделал».
Форма еженедельного ввода лид-показателей: план/факт по каждой метрике из 2.5.
Форма ввода финансовых фактов: сумма по каждому направлению за неделю/месяц.
3.2. Расчёты и аналитика
Execution Score (еженедельный).Формула: (сумма выполненных лид-показателей / сумма плановых лид-показателей) × 100%, отдельно по каждому направлению и сводно по всем. Порог нормы — 85%. Если ниже — статус «риск», если 85%+ — «в графике».
Прогресс к финансовой цели блока (лаг-показатель).Для каждой цели (G1, G2, G3): (текущий факт − стартовое значение блока) / (целевое значение блока − стартовое значение блока) × 100%. Показывает % выполнения промежуточной цели блока.
Сопоставление лид- и лаг-показателей (ключевая логика приложения).Раз в неделю приложение должно сравнивать: растёт ли execution score (действия) синхронно с ростом факта по деньгам (результат). Возможные сценарии и сигналы:
Execution score ≥85% И факт по деньгам растёт по графику → сигнал «зелёный»: всё в порядке, продолжать.
Execution score ≥85% НО факт по деньгам НЕ растёт (или растёт медленнее плана) → сигнал «жёлтый»: действия выполняются, но не конвертируются в результат — нужно пересмотреть тип действий (не то делаем) или увеличить объём.
Execution score <85% И факт по деньгам не растёт → сигнал «красный»: явное отставание и по действиям, и по результату — нужна немедленная корректировка плана.
Execution score <85% НО факт по деньгам всё равно растёт → сигнал «синий/нейтральный»: результат идёт по инерции или из другого источника — не снижать активность, но зафиксировать нетипичность.
Прогноз (простая линейная экстраполяция).На основе текущей скорости роста факта (за последние 2-3 недели) — рассчитать прогнозируемое значение на конец блока и на 31 декабря. Если прогноз ниже цели — вывести предупреждение с указанием, на сколько ₽/нед нужно нарастить темп.
3.3. Дашборд (главный экран)
Должен показывать одним взглядом:
3 цели с прогресс-барами (факт/цель на текущий блок и на весь цикл)
Execution score текущей недели по каждому направлению
Сигналы (зелёный/жёлтый/красный/синий) по каждой цели с коротким текстовым пояснением, что делать
Список задач текущей недели со статусами
Блок «на что обратить внимание» — автоматически сформированный текст на основе сигналов (например: «Сообщество: посты публикуются по плану, но новых подписчиков нет 2 недели подряд — пересмотреть формат контента»)
3.4. Отчёты по блокам
По окончании каждого блока (09.10, 05.11, 02.12, 31.12) — сводный отчёт: факт по 3 целям vs промежуточная цель блока, средний execution score за блок, список невыполненных задач с переносом в следующий блок, рекомендация по корректировке промежуточной цели следующего блока.
4. Нефункциональные требования
Локальное использование (не требует облачного развёртывания), данные хранятся в файле/локальной БД.
Простой, минималистичный UI без лишней навигации — форма ввода и дашборд должны быть доступны в 1-2 клика.
Возможность экспорта данных в CSV для внешнего анализа.
Не требуется многопользовательский режим, авторизация — не критична для MVP.
5. Приоритет реализации (MVP → далее)
Ввод задач и еженедельных лид-показателей (план/факт) + расчёт execution score.
Ввод финансовых фактов + расчёт прогресса к целям блока.
Логика сигналов (зелёный/жёлтый/красный/синий) и текстовые рекомендации.
Дашборд со сводной визуализацией.
Прогноз/экстраполяция и отчёты по итогам блока.
