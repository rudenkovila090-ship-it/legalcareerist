# Проверка бота и подписок, 10 ноября 2026

В рабочем окружении нет подключения SSH к Timeweb, ключей Prodamus и базы действующих подписчиков. Исправления проверены на изолированном API с синтетическими карточками. Живые настройки, права бота и названные владельцем карточки проверяет установщик непосредственно на Timeweb; он сохраняет отчёты до и после установки. До запуска команды статусы реальных людей не объявляются исправленными.

## Причины и изменения

- Истечение доступа было связано с обязательной технической отменой Prodamus. Неизвестный договор приостанавливал исключение, а повторная проверка продлевала служебный допуск. Теперь оплаченная дата, общая отсрочка и реальная банковская блокировка определяют доступ; ошибки списания и истечение доступа не отключают договор. Явная отписка клиента и отдельные подписанные действия владельца сохраняют своё поведение.
- Для уже отсутствующего участника выполняется сверка без банковского запроса и без повторной проверки подписки. Уведомление об одной причине за один оплаченный период подтверждается отдельно и не повторяется ежедневно.
- Подписанные, ещё не учтённые платежи блокируют исключение. Неподписанный журнал не считается доказательством оплаты. Учтённые платежи без order_id сопоставляются с фактической историей и не создают бесконечную проверку.
- Заявка Telegram, пришедшая до платежа, сохраняется и одобряется после подтверждённой оплаты. Ошибки уведомления администратору не блокируют приглашение. Доставка приглашения и письма подтверждается независимо, с повтором после сетевой ошибки.
- Отключение менеджером выделено отдельно от добровольной отмены. Сведения о прежнем прекращении договора сохраняются; прошедшее отключение не превращается в активный договор и не разрешает новые списания автоматически.
- По указанию владельца Шеманаевой Анастасии создаётся отдельное бесплатное бессрочное право с номинальной меткой 350 ₽: только при однозначной личности и подтверждённом участии. Оно не содержит платежей, не попадает в подбор договора для настоящих оплат и заканчивается при выходе из чата. Повторная установка не возрождает закончившееся право. В боте и кабинете оно называется резидентским, без обозначения «Основатель».
- Оплаченная карточка, уже привязанная к Telegram, не перепривязывается чужой командой /start по старой ссылке.

## Живая проверка и установка

`scripts/install-community-bot-fix.mjs` определяет активные изолированные API по PM2; проверяет хэши изменяемых модулей, однозначные контексты, синтаксис и неизменность остальных библиотек. Сохраняет прежний код; обновляет оба API, если установлен демопроцесс. При ошибке перезапуска возвращает прежний код, не заменяя данные оплат. Фронтенд и Nginx не меняются.

Адресные исправления выполняются внутри основного API через короткоживущий подписанный запрос. Повтор идемпотентен. Неоднозначное имя или недоступный Telegram не дают права угадать ID. После адресной сверки запускаются обработка подтверждённых платежей и штатный контроль доступа.

`scripts/audit-community-bot.mjs` читает конфигурацию, историю и карточки Дианы, Светика, Панкрата, Артёма, Анастасии, Олеси и Ксении. Проверяет Telegram getMe/getWebhookInfo/getChatMember и права приглашать/исключать; локальный API и публичную форму подписки без создания заявки; отказ принимать неподписанный вебхук. Секреты, bearer-токены карточек и полный денежный журнал не выводятся. Ключевые категории ошибок PM2 подсчитываются без публикации исходных логов. Отчёт отличает записанный биллинговый статус от фактического права доступа.

Статус `BOT_FIX_READY` означает, что установка и контрольные проверки завершены; далее выводятся строки CASE с фактическим результатом сверки. Полные закрытые отчёты сохраняются в `/root/legalcareerist-bot-backups/`. Недоступность внешнего сервиса и повреждение истории не маскируются успешной готовностью.

## Проверки

- 94 модульные проверки сроков, платежей, отписки, возврата, принадлежности карточек и новых регрессий.
- HTTP: 30 базовых проверок, 20 полного цикла, 20 удержания цены, 13 восстановления, 20 адресного исключения, 26 синхронизации и новых сценариев.
- Четыре сценария установщика: установка и повтор; неизвестный исходник; отказ перезапуска; отказ проверки здоровья. Данные денег и посторонние модули сохраняются, ключи не печатаются.

В этих тестах все Telegram, SMTP и Prodamus подменены. Настоящее списание с банковской карты не выполнялось.
