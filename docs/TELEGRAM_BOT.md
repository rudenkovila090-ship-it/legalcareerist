# Telegram-бот @LegalcareeristBot

Бот работает **сам, без Meta, посредников и зарубежных сервисов**: он опрашивает Telegram (long polling) и не требует ни домена, ни сертификата, ни входящих подключений. Ему нужен только доступ с сервера к `api.telegram.org`, поэтому его можно запускать на сервере в РФ (проверьте доступность Telegram с вашего сервера командой `--check`).

Что умеет:
- **воронки выдачи материалов** по кодовому слову или диплинку: вопросы кнопками, проверка подписки на канал, выдача, напоминание, опрос, дожим ([FUNNELS.md](FUNNELS.md));
- **приветствие** по имени при входе в бот;
- **диплинки** на любой шаг бота (для Instagram, QR, рекламы);
- **анкеты** (заявки): меню, вопросы с кнопками и проверкой телефона, согласие на обработку данных;
- **карточки заявок** менеджерам; ответ менеджера на карточку уходит клиенту;
- **метки, источники, статистика** и выгрузка в CSV.

## Как это работает для клиента

1. Клиент попадает в бота по ссылке с меткой (`https://t.me/LegalcareeristBot?start=guide__ig_story`) или находит бота сам и нажимает «Запустить».
2. Видит приветствие по имени с кнопками (гайд, лонглист, вакансии, мероприятие, консультация, сообщество).
3. Нажимает кнопку или пишет кодовое слово («гайд»): запускается воронка. Для заявок бот задаёт 2–3 коротких вопроса (если задан `PRIVACY_URL`, сначала спросит согласие на обработку данных).
4. В чат менеджеров приходит карточка: сегмент, источник, имя и ссылка на клиента, ответы, метки.
5. Менеджер **отвечает (reply) на карточку**, и ответ уходит клиенту от имени бота (текст, фото, файлы, голосовые). Пока менеджер ведёт диалог, бот молчит, а новые сообщения клиента приходят менеджеру.

Слова «менеджер» (позвать человека), «стоп» (отказ от автосообщений) и «меню» работают на любом шаге. Тексты правятся в `config/flows.json` (анкеты) и `config/funnels.json` (воронки) без программиста.

## Запуск

Нужно: Python 3.12+ или Docker, токен бота, группа менеджеров.

### 1. Токен и группа
- Токен: BotFather → ваш бот → API Token → `TELEGRAM_BOT_TOKEN`.
- Создайте группу менеджеров и добавьте в неё @LegalcareeristBot.
- Узнайте ID группы:

```bash
export TELEGRAM_BOT_TOKEN=...             # токен из BotFather
python -m bridge.tgbot --find-chat        # затем за 60 секунд напишите в группе /chatid
```

Скрипт напечатает ID группы (начинается с `-100…`). Он ничего не подтверждает в Telegram, поэтому сообщения не потеряются. Если группа не находится, проверьте в BotFather → Bot Settings → Group Privacy, что бот видит команды.

### 2. Настройка
```bash
cp .env.example .env     # заполните TELEGRAM_BOT_TOKEN, TELEGRAM_MANAGER_CHAT_ID, PRIVACY_URL, SUBSCRIBE_CHANNEL
set -a; . ./.env; set +a
pip install -r requirements.txt
python -m bridge.tgbot --check --test-message
```

`--check` проверяет токен, отсутствие чужого webhook, доступ бота к группе и к каналу, какие воронки работают, и показывает предупреждения. `--test-message` присылает менеджерам тестовое сообщение. Запускайте только после зелёных ✅.

**Проверка подписки на канал:** добавьте бота **администратором канала** (права не нужны) и задайте `SUBSCRIBE_CHANNEL=@имя_канала`. Без этого Telegram не покажет боту список подписчиков, и воронки выдают материал без проверки (в логах и в группе менеджеров появится предупреждение).

### 3. Запуск
```bash
python -m bridge.tgbot
```

В продакшене запускайте как сервис с автоперезапуском (Docker, systemd). Базу (`DB_PATH`: заявки, контакты, метки, отложенные сообщения) держите на постоянном диске.

```bash
docker build -t legalcareerist-bot .
docker run -d --restart=always -v bot-data:/data --env-file .env legalcareerist-bot python -m bridge.tgbot
```

Образ собран для общего запуска (мост Instagram + бот). Для одного Telegram-бота команда `python -m bridge.tgbot` в конце обязательна. Сборку Docker-образа я не проверял: в среде не было Docker-демона. Первый запуск проверьте командой `docker logs`.

## Если @LegalcareeristBot уже где-то работает
У одного токена может быть только один «слушатель». Бот откажется стартовать, если у токена включён webhook (в `--check` будет ❌), и покажет ошибку `Conflict`, если уже работает другой опрос. Что делать:
- остановить старый процесс (лучше всего: тогда весь функционал будет в этом боте), либо
- завести у BotFather **нового** бота и использовать его токен, либо
- запустить с `TG_FORCE_POLLING=1`: webhook удалится, а старый процесс перестанет получать сообщения. Делайте это, только если вы уверены.

## Отписка от сообщества с обратной связью

Путь выхода намеренно длиннее обычной отписки: так мы понимаем, что пошло не так.

1. Клиент запускает путь командой `/unsubscribe` или ссылкой `https://t.me/LegalcareeristBot?start=unsub` (её можно поставить за кнопкой «Отписаться» в вашем меню).
2. Бот показывает 14 причин списком (формулировки дословно из `config/exit_survey.json`) и кнопки с номерами. Причин можно отметить несколько. Номер с галочкой ✅ значит «отмечено», повторное нажатие снимает отметку.
3. Если отмечено «Другое», бот просит написать причину своими словами и сохраняет ответ.
4. Кнопка **«Продолжить»** принимает ответ, только если отмечена хотя бы одна причина. Пока её не нажали, кнопки «Отписаться» не видно вообще.
5. После «Продолжить» появляются **«Отписаться от сообщества»** и **«Остаться в сообществе»**.
6. «Отписаться»: менеджеру приходит карточка с причинами, на клиента ставится метка `exit:left`; если задан `COMMUNITY_CHAT_ID`, бот удаляет человека из чата сообщества (бот должен быть администратором; человек не блокируется и может вернуться по ссылке). «Остаться»: благодарность, карточка менеджеру, метка `exit:stayed`.

Менеджеру: `/stats` показывает, сколько отписалось, сколько осталось и частоту каждой причины, `/exits` присылает файл CSV со всеми ответами.

**Чего бот не делает:** не отключает платёжную подписку. Он не знает вашего платёжного провайдера, поэтому карточка менеджеру напоминает подтвердить отписку и отключить оплату вручную. Автоматическое отключение возможно, если подключить API вашего платёжного сервиса.

## Сообщения о подписке

Тексты трёх сообщений (поздравление с оплатой, напоминание о списании, уведомление о списании) лежат в `config/subscription.json`. В них можно ставить `{first_name}`, `{plan}`, `{amount}`, `{date}`, `{until}`. Правьте текст и снова пишите `/testsub`: перезапускать бота не нужно.

Сейчас это только тексты и проверка. Сами сообщения клиентам не уходят, пока не подключён приём оплаты: бот не знает вашего платёжного сервиса и не видит, когда клиент оплатил или когда будет списание.

## Если пишут не кнопками

Кодовые слова выключены (`"keywords_enabled": false` в `config/funnels.json`). Если человек пишет текст мимо кнопок, бот сначала повторяет меню, на второй раз присылает подсказку: «Дорогой друг, используй кнопки, чтобы ориентироваться в боте. Или напиши свой вопрос следующим сообщением: мы передадим обращение в техподдержку и свяжемся с тобой напрямую». Следующее сообщение уходит менеджерам карточкой «Обращение в техподдержку», дальше диалог ведёт человек. Тексты: `nudge` и `support_ack` в `config/flows.json`.

## Диплинки и Instagram

Команда `python -m bridge.tgbot --links` печатает готовые ссылки на каждую воронку и анкету. Суффикс `__метка` записывает источник: `guide__ig_story` = воронка «гайд», источник `ig_story`. Метка видна в карточке, в `/leads`, в `/contacts` и в выгрузках. Допустимы латиница, цифры, `_` и `-`, до 64 символов.

Как связать Instagram и бота без Meta API:
- **Автоответ в Instagram** (Meta Business Suite → Inbox → Автоматизации → «Свои ключевые слова») отправляет клиенту короткий текст и диплинк на бота: `https://t.me/LegalcareeristBot?start=guide__ig_dm`. Дальше всё ведёт бот ([FUNNELS.md](FUNNELS.md)).
- Шапка профиля: `?start=hello__ig_bio`. Сторис: `?start=guide__ig_story`. Афиша мероприятия: QR на `?start=event__qr_jazz2`.
- Автоответы Instagram работают, только если к аккаунту не подключён другой чат-бот (например, BotHelp).

## Команды

В чате менеджеров:
- `/leads`: последние 10 заявок;
- `/export`: все заявки файлом CSV (открывается в Excel и Google Таблицах; значения, похожие на формулы, экранируются);
- `/contacts`: все, кто писал боту, с источниками и метками (CSV);
- `/stats`: статистика воронок, причины ухода из сообщества и какие воронки отключены;
- `/exits`: ответы тех, кто хотел уйти из сообщества (CSV);
- `/testsub`: присылает вам в личные сообщения три тестовых сообщения о подписке (оплата прошла, напоминание о списании, списание выполнено); работает в чате менеджеров и в личной переписке с ботом (если вы участник чата менеджеров) и только если вы хоть раз нажимали «Старт» у бота;
- `/help`: подсказка.

В любом чате: `/chatid` показывает ID чата. Остальные команды работают только в чате менеджеров, посторонние группы бот игнорирует.

## Персональные данные

Бот собирает контакты и сведения о запросе. Это персональные данные:
- задайте `PRIVACY_URL` со ссылкой на политику обработки данных. Тогда бот запросит согласие до сбора контактов (без этой переменной шаг пропускается, а `--check` предупредит);
- вопросы для клиентов юрфирмы намеренно общие («какая тема»), чтобы подробности дел не оставались в переписке бота. Не добавляйте вопросов о деталях дела;
- заявки и контакты хранятся в SQLite-файле на вашем сервере. Организуйте доступ к серверу и резервные копии, определите срок хранения;
- токен бота и содержимое `.env` не публикуйте. Если токен попал в чужие руки: BotFather → ваш бот → API Token → Revoke current token.

Текст и юридическую форму согласия согласуйте с вашим юристом.

## Что проверено

Автотесты (174) и сквозной запуск настоящего процесса против локального имитатора Telegram: приветствие, нажатия кнопок, воронки, анкеты с проверкой телефона, карточка менеджеру, ответ менеджера клиенту, напоминания по расписанию, команды менеджера, сохранение позиции опроса, отсутствие токена в логах.

**Не проверено вживую:** обращения к настоящему Telegram (в том числе проверка подписки на канал) и Docker-образ. Первый запуск начните с `--check --test-message`.
