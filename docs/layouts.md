# Схемы страниц сайта: словарь «называем одним словом»

С 28.10.2026 у сайта единый набор схем страниц. Владелец называет схему одним словом («сделай по схеме Split Screen»), разработчик берёт готовый компонент из `src/components/layouts/` и получает нужный макет с первой попытки. Новая страница сначала выбирает схему из этого списка; новую схему добавляют сюда и в `.claude/skills/legalcareerist-design/SKILL.md`, а не рисуют «на глаз».

## Семь схем

| Схема | Для чего | Компонент |
|---|---|---|
| **Hero Landing + Z-Pattern** | страница услуги: подбор юристов, мероприятие, членство в сообществе | `HeroLanding`, `ZPattern` |
| **Single Column** | блог, статьи, новости, юридические тексты | `SingleColumn` |
| **Two Column** | база вакансий, кандидатов, каталог маркетплейса | `TwoColumn` |
| **Holy Grail** | личный кабинет | `HolyGrail` |
| **Masonry** | фотоотчёты с мероприятий, любые картинки разной высоты | `Masonry`, `PhotoMasonry` |
| **Magazine / Asymmetrical** | афиша мероприятий, кейсы, подборки | `Magazine` |
| **Split Screen** | пока нигде не применена (компонент готов) | `SplitScreen` |

Импорт: `import { SplitScreen, TwoColumn } from '../components/layouts'`.

### Hero Landing + Z-Pattern
```
┌──────────────────────────────────────────┐
│  Заголовок-выгода          [  картинка ] │  ← Hero: одна кнопка «Оставить заявку»
│  одна строка пояснения                   │
│  [ Оставить заявку ]                     │
├──────────────────────────────────────────┤
│  [ картинка ]   Блок 1: текст            │  ← Z-Pattern: взгляд идёт буквой Z
│  Блок 2: текст   [ картинка ]            │
│  [ картинка ]   Блок 3: текст            │
├──────────────────────────────────────────┤
│  Тот же призыв и форма (#apply)          │
└──────────────────────────────────────────┘
```
Правила: на первом экране **одна** главная кнопка, и для услуг с заявкой (подбор юристов и т. п.) это «Оставить заявку» (`cta` в `HeroLanding`); у членства в сообществе главная кнопка остаётся «Вступить» (решение владельца 28.10.2026); вторых кнопок и ссылок-«конкурентов» в Hero нет; в конце страницы тот же призыв и форма с адресом `#apply`; на телефоне картинка над текстом.

### Single Column
```
        ┌────────────────────┐
        │  Заголовок         │   ширина до 48 rem (`prose`),
        │  Текст текст текст │   формы и короткие страницы — 36 rem (`narrow`),
        │  Текст текст текст │   текст с крупными вставками — 56 rem (`wide`)
        └────────────────────┘
```
Правила: одна колонка по центру, строка 65–75 знаков, ничего по бокам; «Читайте также» — под текстом.

### Two Column
```
┌─────────┬──────────────────────────┐
│ Фильтры │  Карточка   Карточка     │   слева 16,25 rem (sticky), справа список
│ (слева) │  Карточка   Карточка     │
└─────────┴──────────────────────────┘
```
Правила: фильтры только слева; на телефоне они над списком и сворачиваются кнопкой «Фильтры» (`collapseLabel`); число найденного — над списком; колонка фильтров поднята над списком (`z-20`), чтобы раскрывающиеся списки не прятались под карточками.

### Holy Grail
```
┌──────────────── шапка сайта ────────────────┐
│ меню слева │   содержимое   │ справа (по    │
│ (sticky)   │                │ желанию)      │
├──────────────── подвал сайта ───────────────┤
```
Правила: шапку и подвал рисует общий `Layout`; слева меню (на телефоне пилюли), по центру содержимое, справа необязательная колонка (подсказки, сводка). Кабинет резидента сейчас без правой колонки.

### Masonry
```
┌──────┐┌──────┐┌──────┐
│ фото ││ фото ││ фото │   колонки заполняются сверху вниз,
│      ││      │└──────┘   высота снимков разная, дыр нет
└──────┘└──────┘┌──────┐
┌──────┐ ┌──────┐│ фото │
```
Правила: 1 колонка на телефоне, 2 на планшете, 3 на компьютере; меньше трёх снимков показываются ровным рядом; у каждого снимка `alt` и ленивая загрузка (`PhotoMasonry`).

### Magazine / Asymmetrical
```
┌────────────────┬───────┐
│                │ малая │   первый материал крупный (2 колонки × 2 строки),
│  главный       ├───────┤   остальные мельче вокруг него
│                │ малая │
├───────┬────────┴───────┤
│ малая │ малая │ малая  │
```
Правила: «герой» — ближайшее или главное событие; меньше трёх материалов — ровная сетка.

### Split Screen
```
┌───────────────┬───────────────────┐
│               │ тип · дата · город │
│    афиша /    │ Название          │
│    фото       │ [ Регистрация ]   │
│  (остаётся    │ Регистрация       │
│  на месте)    │ Важные даты       │
│               │ Программа ...     │
└───────────────┴───────────────────┘
```
Правила: слева фото или афиша (на компьютере прилипает при прокрутке), справа название, регистрация, программа, документы, организатор; на телефоне фото сверху. Без афиши слева цветная плашка с большой датой.

| Личный кабинет резидента `/cabinet` | Holy Grail | ✅ применена (`HolyGrail`), правой колонки нет |

| Афиша `/events` | Magazine | ⬜ сейчас ровная сетка и широкая карточка вечера; компонент готов, включим, когда мероприятий станет три и больше |
| Фотоотчёты с мероприятий `/events/:slug/photos` | Masonry | ✅ страница и просмотр на весь экран готовы (`EventPhotos`, `Lightbox`); ждёт реальных снимков, как добавить — `docs/photo-reports.md` |
| Кейсы | Magazine | ⬜ раздела пока нет |
| Главная `/` | отдельная схема не нужна: это страница-вход с четырьмя плитками разделов (Кадры, Сообщество, Мероприятия, Маркетплейс) | 🔶 оставить как есть; блоки ниже (доверие, цифры, новости) можно разложить зигзагом, решение владельца |
| Работодателям `/kadry`, подбор юристов | Hero Landing + Z-Pattern | ⬜ длинная страница из 10 блоков и многих кнопок (по коду около 22 пилюль-кнопок, часть из них метки): приводить к одной «Оставить заявку» в Hero и одной форме в конце; нужна проверка глазами |
| Соискателям `/kadry/candidates`, кадровый резерв, карьерные консультации | Hero Landing + Z-Pattern | ⬜ то же (по коду пилюль-кнопок: консультации 16, резерв 6, соискателям 5) |
| Сообщество `/community` | Hero Landing + Z-Pattern | ⏸ главная кнопка остаётся «Вступить» (выбор тарифа и оплата), страница «как есть» (решение владельца 28.10.2026); раскладка блоков зигзагом пока не планируется |

Порядок дальнейших работ (предложение): лендинги услуг — сначала `/kadry` (подбор юристов), затем соискатели, резерв и консультации; потом афиша (Magazine). Сообщество и вечер «Джазовый вечер для юристов 2» не трогаем. Какой лендинг идёт следующим, подтверждает владелец.

## Общие правила для всех схем

- Контейнеры: `container-page` (76 rem) для страниц сайта, `container-wide` (96 rem) для кабинета. Свою ширину не придумываем.
- На телефоне любая схема складывается в одну колонку в порядке: картинка → текст → действия; горизонтальной прокрутки нет (проверка: ширина документа не больше ширины окна на 360/390/768 px).
- Прилипающие колонки (`sticky`) стоят ниже шапки сайта: `top-24` (в кабинете `top-20`).
- У страницы один `h1`, у экрана одна главная кнопка.
- Цвета, шрифт и карточки — из дизайн-системы (`.claude/skills/legalcareerist-design/SKILL.md`), схема отвечает только за раскладку.
